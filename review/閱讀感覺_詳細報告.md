# 閱讀感覺 · 詳細報告

**前置**：這份報告在 `閱讀感覺_第一印象.md` 寫完並封存之後才動筆。
第一印象是純讀者感受；這一份是回頭去查證那些感受站不站得住，以及找出成因。

**查證範圍**：三張卡的 `.md` 原檔、`build_site.py`、`assets/style.css` 的 `@media print`、
`img/<字>/` 目錄。沒有看過 git 紀錄、沒有看過 `review_dedupe.py`、沒有看過任何計劃檔案。

## 零、先修正第一印象裡兩個不準確的地方

做評論的人自己也要交代錯在哪。有兩處要更正：

### 更正一：財那張「印了兩次的楷書並排圖」，原檔已經修好了

第一印象裡我說財 p.11 和 p.15 印了同一張「財／材／裁／貨」的圖，
並說這是「最刺眼」的一處。**這在 PDF 上是事實，但在 `.md` 原檔上已經不成立。**

`財.md` 第 376 行現在寫的是：

> **【觀察】楷書並排（我看過的圖，圖表見 1.4）：**

後面直接接文字，**沒有再貼表格**。而 `pdf/財.pdf` p.15 抽出來的文字是：

> 【觀察】 楷書並排（我看過的圖）：
> 財　材　裁　貨　貝+才　木+才　衣+𢦏　貝+化

**沒有「圖表見 1.4」那五個字，而且表格還在。**

結論：**這三份 PDF 比現在的 `.md` 舊。** 有人已經把這一處重覆改成「指回去」，
只是 PDF 未重新生成。我在第一印象裡的抱怨是對着一份過期的成品發的。
這一處我收回，並且要說：**那個改法（把重覆的表改成一句「圖表見 1.4」）正是對的做法**，
下面第三節我會建議把同樣的手法用在其餘幾處。

> 附帶一提：既然 PDF 落後於 `.md`，委託人如果要拿最新版來判斷厚薄，
> 應該先重新 build 一次。我沒有動手 build（本次任務只准我在 `review/` 寫東西）。

### 更正二：「九成重疊」這個數字講得太重

第一印象裡我說總覽的「同族字」「做部件時」跟 1.7／1.8「九成重疊」。
實測**字面**重疊沒有那麼高：

| 比較 | 結果 |
|---|---|
| 靜：總覽兩格（542 字） vs 1.7+1.8（2229 字），六字片段重疊率 | **24%** |

**但重點在這裡**——換個量法，結論完全反過來：

| 量的是甚麼 | 結果 |
|---|---|
| 總覽「做部件時」出現的**數字**（108、30、6、7） | **4 個全部**在 1.8 重現 |
| 總覽「做部件時」引的**字例**（瀞、財、靜…） | 5 個中 3 個重現 |
| 總覽「同族字」引的**字例**（青、爭、才、財、靜） | **5 個全部**在 1.7 重現 |

**也就是說：句子不同，但事實一模一樣。**

這正好解釋了為甚麼讀起來特別累。
如果是整段原文照抄，讀者一眼就認得出「這是引用」，跳過去就算；
但**同一批數字、同一批字例，用不同的句子再講一次**，讀者非要讀完整段才發現沒有新東西。
**這是最耗神的一種重覆**，也是最難靠肉眼察覺的一種——難怪讀者只能形容成一個模糊的
「好似啲資料前面同後面會有重覆」。

所以：**「九成」這個數字我收回，但「重覆感成立」這個結論不但站得住，而且成因比我原先想的更精確。**

## 一、真正的成因：PDF 把一個為網站設計的三層結構壓平了

這是查證之後最重要的發現，它解釋了幾乎全部症狀。

### 網站上，第 3 層是摺埋的

`build_site.py` 第 383 行：

```python
def detail_html(md, card, root, open_default=False):
    ...
    return ('<details class="deep"%s><summary>%s ...'
            % (' open' if open_default else '', ...))
```

單字頁用的是 **`open_default=False`**。
也就是說，讀者打開網站，預設看到的只有：

> 大字 → 密集資料格 → 推理網絡圖 → 字形演變帶 → **總覽七格** → 〔詳細考證（摺埋，要撳）〕

**這個設計是完全成立的。** 總覽是摘要，詳細考證是展開，
讀者不撳就不會見到 1.7、1.8、2.2，自然不會有任何「剛才看過」的感覺。

### 但 PDF 用的是展開版，而且連分界線都拿掉了

`build_site.py` 第 508 行，砌 `all.html`（PDF 的來源）時：

```python
detail_html(md, c, root, open_default=True),
```

**強制展開。** 這一步是必要的——紙本不可能「撳開」。

問題出在下一步。`assets/style.css` 的 `@media print` 裡：

```css
details.deep > summary { display: none; }
```

**「詳細考證」那個標題，在列印版被隱藏了。**

於是紙本上發生的事是：

> 總覽「其他結果」最後一點
> ↓（一段灰色小字：「以下是完整的原始資料…標記：…」）
> ↓
> **0. 基本資料**

讀者**完全看不到任何東西告訴他「上面那五頁是摘要，下面開始是原始材料」**。
摘要和正文變成前後相連的兩段正文。於是：

- 在網站上，1.7 是「你撳開之後看到的細節」
- 在 PDF 上，1.7 是「第 16 頁又講了一次第 3 頁講過的東西」

**同一份內容，同一個作者，讀者感受完全相反——分別只在有沒有那條分界線。**

### 這件事的意思

**讀者抱怨的「重覆」，不是寫作問題，是輸出問題。**
一句考據都不用刪、一個段落都不用改，**只要紙本恢復分層，感覺就會大幅改善。**
下面第三節的「甲」和「乙」兩條就是針對這一點。

## 二、逐項查證：第一印象裡的指控，哪些站得住

### ✅ 站得住（而且比我想的更硬）：首頁資料格 vs 0 節基本資料表

    ...

**這一條我原封不動保留。** 它是三份裡最硬、也最容易解決的一處重覆。

## 三、只改排版的具體建議（一句內容都不刪）

按「省得最多 ÷ 改動最小」排序。**每一條都不需要動任何一個字的考據。**

### 甲、紙本上，0 節那張表不要再排一次 〔省 1–1.5 頁／卡〕

首頁密集格已經是它的完整重排（`info_html` 一項不漏）。
`@media print` 裡把 0 節那張表隱藏，或者反過來——首頁不出密集格、0 節保留表。

**我建議保留首頁那條格、隱藏 0 節的表**，理由是讀者感受：
那條格是三份 PDF 裡我最喜歡的東西之一，一眼掃完就有個底；
而 0 節那張直排大表，讀到第 5 頁才出現，位置很尷尬（緊接在「其他結果」之後）。

> 若擔心來源欄會連帶失去：首頁那條格現在不顯示「來源」。
> 可以把來源收進格子的 title／細字，或者 0 節只保留「項目｜來源」兩欄的窄表。

### 乙、紙本上，把「詳細考證」的分界線加回去，而且要加粗 〔省 0 頁，但效果最大〕

現在 `@media print` 是 `details.deep > summary { display: none; }`。
**建議反過來做**：

- `summary` 在列印版**顯示**，而且**強制分頁**（`break-before: page`）
- 排成一整頁或半頁的間隔頁，寫清楚：
  **「以上是結果。以下是完整的原始資料、字典原文與考證過程。」**

**這一條省不到一頁，但我認為它是所有建議裡最重要的一條。**
讀者抱怨的「重覆」，一大半來自看不到那條線。
有了線，1.7 就由「第 16 頁又講一次」變回「你要的細節在這裡」。

### 丙、1.6 和 2.2 合併 〔省 1–2 頁／卡〕

12/12 的引文重覆。兩個改法，任擇其一：

1. **1.6 那張表的「一句字典義」欄改成「見 2.2」**，表保留（它的層級／粵音／出處欄是獨有的）；
2. 或者反過來，**2.2 只補 1.6 沒有的部分**（「凡 X 之屬皆从 X」那截、其餘字典、小結）。

**我傾向第 1 種**：1.6 那張表的價值在「拆到獨體象形為止」這個層級結構，不在引文。

### 丁、字形演變帶和 1.1 的圖，紙本上二擇一 〔省 0.5–1.5 頁／卡，發最多〕

- **靜、財**：首頁演變帶 7 格，1.1 再列 9–10 格。建議 1.1 的表保留（有【觀察】貼着），
  **首頁演變帶縮成一行細圖**。
- **發**：首頁 12 格佔大半頁，1.1 再列 13 格。**發省得最多**，
  首頁那條帶縮成一行，可以省近一頁。

### 戊、1.7／1.8 的表改成細字窄行，正文只留「圖以外」的東西 〔省 1 頁／卡〕

不是刪表。總覽已經用圖卡給過同一批字和同一批《說文》，
1.7／1.8 的表改用細字、窄行、貼着排；正文保留圖上看不到的那幾點：

- 1.7「三、這個交叉點告訴我們甚麼」那三點（**這幾點是全節最有價值的，圖上沒有**）
- 1.7「四、部件在別的字裡的位置」
- 1.8「三、這說明甚麼」

### 己、清單類一律兩欄 〔省 1.5–2 頁／卡〕

- 存疑／未驗證（11／13／**18** 條）
- 來源清單（18／13／14 項）
- 同音異調字（靜 p.26、財 p.20、發 p.18——財那節 coi1 只有一個字、coi5/6「有音無字」）
- 靜 p.19 那兩份義項清單（異體字字典 7 項 + 重編國語辭典 6 項），**改成左右並排的對照表**

### 庚、推理網絡圖移到總覽之後 〔省 0 頁，改善入口〕

維持第一印象的判斷。那幅圖上寫的「三說都走不通」「同音表是結構鏡像」全部是**結論**，
放在讀者甚麼都未知道的第 1 頁只能看個熱鬧。
放在總覽七格之後，每個節點讀者都認得，圖立刻變得有用。

**第 1 頁留：大字 + verdict 標語 + 密集資料格。** 那是最好的開場。

### 辛、發要加東西，不要減 〔多 2–3 頁，但好讀得多〕

發的問題從來不是重覆——它 30 頁裡我一次都沒有「剛才看過」的感覺。
它的問題是**沒有入口**：讀到 p.16 才第一次見到全景，p.20 才見到結論，前 15 頁全是原始材料。

**升 v3（加 front matter、網絡圖、總覽七格）會令它多兩三頁，但會令它好讀得多。**
連同書面語遷移（70 處口語），這兩件事我認為優先於任何減頁工作。
